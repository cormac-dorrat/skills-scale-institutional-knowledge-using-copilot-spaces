# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management process documentation hub. This directory contains comprehensive guidance for running projects at OctoAcme, organized by lifecycle phase.

## Overview

OctoAcme follows a structured, iterative approach to project management with these core principles:
- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Project Lifecycle

All OctoAcme projects follow five key phases:

1. **Initiation** → Define problem, align stakeholders
2. **Planning** → Break work into increments, identify dependencies
3. **Execution** → Build, test, iterate
4. **Release** → Deploy safely, verify
5. **Close & Retrospective** → Capture learnings

## Key Artifacts by Phase

### Initiation
- Project One-pager (Problem, Goal, Success Metrics)
- Stakeholder list & communication plan
- Initial risk list

### Planning
- Prioritized backlog with acceptance criteria
- Definition of Done (DoD)
- Release plan and milestone map
- Risk Register

### Execution
- Sprint/Iteration backlog
- Project board (GitHub Projects)
- Pull Request workflow with CI automation
- Quality gates and testing strategy

### Release
- Release notes
- Deployment checklist
- Rollback & incident playbook

### Retrospective
- What went well / What could improve
- Action items with owners and due dates
- Continuous improvement tracking

## Communication Cadence

- **Daily standups** (15 min) — progress, blockers, dependencies
- **Weekly sync** — PM + PdM alignment
- **Twice-weekly delivery standups** — team coordination
- **Weekly stakeholder updates** — status and decisions needed
- **Monthly strategic reviews** — roadmap and metrics
- **Post-sprint retrospectives** — learnings and improvements
